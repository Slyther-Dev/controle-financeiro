Guia de Arquitetura & Apresentação Técnica

Visão detalhada sobre os padrões de projeto utilizados nesta aplicação

1. Paradigma & Arquitetura (State-Driven UI)

Este projeto adota o padrão de Interface Guiada por Estado (State-Driven UI) utilizando JavaScript Vanilla puro, sem dependências de frameworks pesados como React ou Vue. Todo o estado financeiro reside em um objeto centralizado (AppState). Qualquer modificação no estado dispara re-renderizações previsíveis e reativas na DOM e nos gráficos.

2. Módulos & Separação de Responsabilidades (SOC)

StorageManager

Isola o acesso à API do localStorage do navegador, garantindo serialização e tratamento de exceções (try/catch).

FinanceService

Regras de negócio puras: cálculo de saldos, agregação de receitas/despesas e agrupamento categórico para os gráficos.

ChartManager

Gerencia a renderização e o ciclo de vida dos gráficos (Chart.js), prevenindo memory leaks via destruição segura das instâncias antigas.

UIManager

Manipulação eficiente do DOM, escuta de eventos, badges de categoria, formatação de moeda BRL e animações visuais.

3. Formatação Padrão Internacional (BRL)

Em vez de regex ou manipulações manuais de strings para formatar moeda, utiliza-se a API nativa do navegador Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' }). Isso garante precisão no padrão monetário brasileiro (R$ 1.250,00).

4. Possíveis Perguntas de Entrevista Tech & Respostas

Q: Por que preferiu modularizar o código em objetos de serviço em vez de colocar tudo num script linear?

R: Para aplicar o princípio DRY (Don't Repeat Yourself) e a responsabilidade única (SRP do SOLID). Isso torna o código desacoplado, facilmente testável e escalável.

Q: Como evitou problemas de travamento ou memory leaks com Chart.js?

R: Antes de instanciar um novo gráfico sobre o mesmo <canvas>, o ChartManager invoca o método chartInstance.destroy() para liberar a memória e a referência anterior do canvas.

Q: Como foi tratada a persistência de dados?

R: Através da API do localStorage com conversão JSON. Ao inicializar a aplicação, o estado é reconstituído a partir do storage. Também foi implementado um mecanismo para popular dados de demonstração rápida (seed data).
